# Space Express (스페이스 익스프레스)

2D 탑다운 우주 배달 게임. 플레이어는 우주선을 조종하여 행성에 식량을 배달하고,
광석을 채취하여 정거장에서 주괴로 제련하는 루프를 반복하며 행성의 번영도를 관리한다.

| 장르 | 엔진 | 개발 기간 | 개발 인원 |
|------|------|-----------|-----------|
| 2D 탑다운 캐주얼 | Unity 6 | 2026.05.16 - 2026.06.05 | 1인 |

## 핵심 게임플레이 루프

**식량 배달 → 행성 번영도 상승 → 광석 채취 → 정거장 제련 → 주괴/골드 획득 → 업그레이드**

## 기술 스택
### 엔진 및 언어
- **Unity 6**, C#
- **Perspective 카메라** — 일반적인 2D 게임의 Orthographic 대신 채택. 모든 오브젝트 Z값을 0으로 고정해 2D처럼 보이도록 유지하면서, 행성 스폰 시 Z축으로 멀어지며 맵을 절차적으로 확장하는 시스템 구현

### 에셋 관리
- **Addressables** — 런타임 에셋 로딩 및 캐싱. 게임 시작 시 UI 테이블 기반 프리팹 일괄 비동기 로드. 스프라이트 시트 캐싱 및 순차 탐색 지원
- **Object Pooling** — 화물 박스 동적 생성/파괴 없이 활성/비활성 전환으로 처리

### 직렬화
- **Newtonsoft.Json** — `Dictionary` 직렬화 및 enum 문자열 파싱 지원. `JsonUtility`로는 불가능한 `GameContext` 구조(`Dictionary` 다수 포함)를 가능하게 함
- **JSON 기반 데이터 테이블** — 스테이지, 행성, 업그레이드, 업적, UI, 사운드 등 전 게임 데이터 관리. 코드 수정 없이 데이터 추가만으로 콘텐츠 확장 가능

### 물리
- **Rigidbody2D + AddForce** — 관성감 유지하되 반응성을 높이는 방향으로 설계. 진행 방향 전환 시 기존 속도를 빠르게 감소시키는 방식으로 조작감 개선
- **SpringJoint2D** — 화물 박스 물리 체인 연결. 화물량에 따라 박스가 순차 추가되는 구조. 최대 거리 초과 시 위치 클램프 및 속도 보정 처리

### 비동기 처리
- **Coroutine** — 번영도 사이클, 정거장 생산, 화물 적재/하역, 인트로 타이핑 애니메이션, 행성 파괴 연출 시퀀스 등 게임 핵심 동작 전반에 활용. `WaitUntil` 기반 코루틴 순차 제어
- **async/await (Task)** — 게임 초기화 시 데이터 테이블 및 UI 프리팹 비동기 일괄 로드

### 패턴 및 설계
- **GameEventBus(직접 구현)** — 타입 안전한 제네릭 이벤트 버스. 파라미터 0~2개 지원. 이벤트 버스 사용 기준 명확화 (1:N 관계 + 같은 생명주기 → 이벤트 / 1:1 또는 다른 생명주기 → 직접 참조)
- **UIBase 패턴** — `PrepareUI → Setup → OpenUI` 3단계 분리로 UI 깜빡임 방지. 슬라이드 애니메이션 내장. BindState 기반 상태 전환 시 자동 열기/닫기
- **GameConfig** — 상수 전용 캐싱 클래스. JSON 상수를 초기화 시 한 번만 캐싱해 단일 진입점으로 관리. 수치 변경 시 JSON 한 줄만 수정하면 전체 반영
- **Simulator / Controller 분리** — 내부 시뮬레이션 로직과 오브젝트 진입점(Controller)을 명확히 분리
- **SaveLoadController** — 슬롯 기반 세이브 시스템. 순수 파일 I/O만 담당

## 개발 과정의 주요 설계 결정

**이벤트 버스 사용 기준 정립**
모든 통신을 이벤트로 처리하다 Unity 생명주기 문제가 반복됐습니다.
비활성 오브젝트가 이벤트를 구독하지 못해 기능이 동작하지 않는 상황이었고,
방어 로직을 추가하는 방식이 아닌 사용 기준 자체를 명확히 정의하는 방향으로 해결했습니다.
- 1:N 관계, 같은 생명주기 → 이벤트 버스
- 1:1 관계, 다른 생명주기 → 직접 참조 + 폴링

**상수 관리 구조 개선**
초기에는 필요한 곳에서 GameDataManager를 직접 참조하는 방식으로 상수를 가져왔습니다.
업그레이드 종류가 늘어나면서 상수 변경 시 참조하는 모든 곳을 찾아 수정해야 하는 문제가 생겼고,
GameConfig 캐싱 클래스를 도입해 단일 진입점으로 해결했습니다.

**코루틴 타이밍 문제 해결**
이전 코루틴이 완전히 종료되지 않은 상태에서 새 트리거가 발생해 중복 실행되거나
실행 자체가 막히는 문제가 반복됐습니다.
코루틴 시작 전 기존 코루틴을 명시적으로 중단하고 상태를 초기화한 뒤
새 코루틴을 시작하는 순서를 엄격히 지키는 방식으로 해결했습니다.
